2. Database Normalization Analysis

First Normal Form (1NF)

• Atomicity: Every column contains atomic (indivisible) values. Customer address, name, phone, and meter numbers are individual fields, not multi-valued lists.

• Unique Rows: Every record is identified by a unique primary key column.

Second Normal Form (2NF)

• No Partial Dependencies: Meets 1NF, and all non-key attributes are fully dependent on the entire primary key.

• Tables utilize surrogate single-column primary keys (e.g. consumer_id, reading_id), naturally eliminating composite key partial dependencies.

Third Normal Form (3NF)

• No Transitive Dependencies: Non-key attributes depend only on the primary key, not on other non-key attributes.

• Slabs belong strictly to tariffs; tariff rates are not stored redundantly in the consumer table.

• Intentional Snapshot in Bills: Line-item charges are stored in bill_items so that future tariff changes do not rewrite historical financial records.

3. ACID Properties Implementation

Atomicity (A):

Bill generation inserts into bills and bill_items and updates meter_readings inside a single database transaction. If any insert fails, all changes are rolled back.

Consistency (C):

CHECK constraints guarantee readings cannot be negative, current reading ≥ previous reading, and bill outstanding amount equals total minus amount paid.

Isolation (I):

Payments utilize SELECT ... FOR UPDATE (Pessimistic Locking) to lock bill rows, preventing concurrent overpayments and lost updates.

Durability (D):

PostgreSQL Write-Ahead Logging (WAL) guarantees that all committed transactions survive system crashes or power failures.
